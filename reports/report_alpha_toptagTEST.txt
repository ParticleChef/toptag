============================================================
1. DEFINITION AND SCOPE — WHY PER REGION
============================================================
toptag/README.md, "Common: Data/MC Normalization Factor alpha":

  In each pT bin, before applying any top-tagging requirement:
      alpha = N(Data) / N(MC)
  This ratio is taken from the RELEVANT CONTROL REGION.

toptag/docs/scalefactors.md:12-13 is more explicit: alpha is
"pre-tag, over *all* processes/jetclasses in the relevant region
(gcr for QCD-jet, tmcr+tecr combined for Top-jet)".

So alpha is indexed by (calibration CR, fjpt bin). It is NOT an
inclusive all-event number, and it is NOT computed per process.

  Measurement        Region(s) for alpha   Data dataset
  -----------------  --------------------  -------------------
  QCD-jet (mis-tag)  gcr                   EGamma
  Top-jet (eff.)     tmcr + tecr, SUMMED   MET (tmcr), EGamma (tecr)

sr, wmcr, wecr, zmcr, zecr never enter alpha.

Confirmed in the reference implementation:
  toptag/scalefactors.py:112-122  gcr only  -> alpha in formula()
  toptag/scalefactors.py:150-170  tmcr and tecr yields are ADDED
                                  first, then ONE alpha is formed

WHY PER REGION: alpha absorbs the normalization mismatch specific
to one CR's process composition and selection (trigger, lepton
ID/isolation, b-tag requirement). It is then used to scale the
MC subtraction terms inside that same CR:

  SF_QCD = [N(Data,tag) - alpha*SF_B*N(GJ,B,tag)] / [alpha*N(GJ,QCD,tag)]
  SF_Top = [N(Data,tag) - alpha*(SF_B*N(B,tag) + SF_QCD*N(QCD,tag))]
           / [alpha*N(Top,tag)]

A single global alpha would be dominated by whichever region has
the most events, and the subtraction would then be biased by the
composition difference between regions — exactly what alpha exists
to remove.

============================================================
2. WHAT WAS COMPUTED
============================================================
  alpha(pT) = N(Data) / N(MC)     [pre-tag]

  N(Data)  = data yield, that region's own dataset only
  N(MC)    = ALL background processes in the file, summed
  pre-tag  = TvsQCD axis SUMMED over fail(bin 0) + pass(bin 1);
             no tagging requirement of any kind
  per bin  = fjpt edges 250, 325, 400, 600, 2000 GeV (4 bins)

Region sets are SUMMED BEFORE the ratio is taken — the combined
ttbar alpha is (D_tmcr + D_tecr) / (M_tmcr + M_tecr), not the
average of two per-region ratios.

Code: plot_alpha_toptagTEST.py

--- Input histogram ---------------------------------------
alpha is read from the `fjpt` histogram, NOT `fjpt_cat`:

  fjpt      region x fjpt x TvsQCD          data IS filled
  fjpt_cat  + n_qinfj x n_binfj axes        bkg only

fjpt_cat has no data because the truth quark / b-flavor matching
that defines the 8 jet classes is undefined for data. alpha needs
no class information, so `fjpt` is sufficient and is the only
option.

Data region coverage in `fjpt` (both files agree):
  MET     sr, wmcr, tmcr, zmcr
  EGamma  wecr, tecr, gcr, zecr

--- Which file for which alpha -----------------------------
Each alpha is taken from the SAME file as the MC it will correct:

  gcr        -> (b) toptagTEST2  the only file with G + Jets,
                                 which the QCD-jet calibration is
                                 defined on
  tmcr+tecr  -> (a) toptagTEST   the file used by
                                 plot_toptag_eff_toptagTEST.py for
                                 the Top-jet efficiency

Mixing them would be wrong: they are different MC test samples
with different absolute normalizations.

--- Uncertainty --------------------------------------------
Data and MC are independent samples, so

  sigma_alpha / alpha = sqrt( var_D/D^2 + var_M/M^2 )

Data variance equals the data yield in every bin (verified), i.e.
data is unweighted Poisson counts. MC variance comes from the
Weight storage.

4. OBSERVATIONS
============================================================
- alpha IS NOWHERE NEAR 1, by 1 to 7 orders of magnitude. On a
  correctly normalized full sample alpha should land within a few
  10% of unity. See section 5 — this is a property of the test
  files, not of the calculation.

- alpha FALLS STEEPLY WITH pT in every region: x220 from the
  first bin to the overflow bin in gcr, x8 in the ttbar CRs. Both
  N(Data) and N(MC) are falling spectra, but the MC yield falls
  much more slowly (it RISES with pT in the ttbar CRs), so the
  ratio drops. A pT-dependent alpha is therefore doing real work
  here and a single inclusive number would be badly wrong even
  within one region.

- THE mu AND e CHANNELS DO NOT AGREE. alpha(tecr) is 36-53%
  higher than alpha(tmcr) in every bin, far outside the quoted
  errors. The combined alpha sits between them by construction.
  Note the contrast with the EFFICIENCIES, which agree between
  the two channels to better than 0.01 in every bin
  (report_toptag_eff_toptagTEST.txt section 5): efficiency is a
  ratio WITHIN one region and is insensitive to normalization,
  whereas alpha is pure normalization. This is consistent with
  the e and mu MC simply being scaled differently in this test
  sample, and is another symptom of section 5.

- gcr alpha is ~10^5 times larger than the ttbar alpha. These
  come from different files and are not comparable; within file
  (b) alone, gcr MC is 1.9e-03 weighted events in the lowest pT
  bin, which is the real driver.

============================================================
5. CAVEATS — READ BEFORE USING THESE NUMBERS
============================================================
- THESE alpha VALUES ARE NOT PHYSICS. N(Data) is the FULL 2022preEE
  dataset (95294 events in the lowest gcr bin), while N(MC) comes
  from a small test sample of a few files that was normalized with
  the FULL sample's sum-of-weights. The MC yield is therefore
  suppressed by roughly the fraction of files processed, and alpha
  is inflated by the inverse of that fraction. The same
  normalization problem is recorded in report_fjpt_toptagTEST.txt
  lines 90-101 ("Data/MC normalization is far off in every
  region").

  What IS validated here: the definition, the region/dataset
  mapping, the pre-tag summation, the per-bin structure and the
  error propagation. Re-run on the full sample before any number
  in section 3 is used in a scale factor.

- SANITY CHECK FOR THE FULL SAMPLE: alpha should come out
  O(1) in every bin and every region, and alpha(tmcr) should
  agree with alpha(tecr) within a few percent. If either fails on
  the full sample, the problem is upstream of this script.

- THE mu/e DISAGREEMENT INVALIDATES THE COMBINED-alpha
  ASSUMPTION AS MEASURED HERE. Summing tmcr+tecr into one alpha
  (the AN convention, and what scalefactors.py does) assumes the
  two channels share a normalization. On this file they do not.
  Do not conclude the convention is wrong — re-test on the full
  sample. If the split survives there, the Top-jet SF should use
  per-channel alpha instead.

- alpha IS PRE-TAG BY DEFINITION. Do not recompute it with a
  TvsQCD cut applied; that would absorb the very tagger
  mismodeling the SF is meant to measure.

- QCD Multijet and G + Jets are absent from file (a) entirely, so
  its gcr MC is incomplete. This is why the gcr alpha is taken
  from file (b). For the record, file (a) gives alpha(gcr) =
  9342 / 5130 / 1817 / 236 over the four bins — do not use it.

- The overflow bin is drawn with a right edge of 1000 GeV. Do not
  read its width as a real pT range; it contains all fjpt >= 600.

============================================================
7. NEXT STEP
============================================================
alpha is the only ingredient of eff_Data that does not need the
jet classes. With it in hand, the data-side efficiency is

  eff_Top,Data = [N(Data,tag) - alpha*N(MC,B/QCD,tag)]
               / [N(Data)     - alpha*N(MC,B/QCD)]

  eff_QCD,Data = [N(Data,tag) - alpha*N(GJ,B,tag)]
               / [N(Data)     - alpha*N(GJ,B)]

Both need the CLASS-SPLIT MC yields, which come from `fjpt_cat`
(plot_toptag_eff_toptagTEST.py already extracts them), and the
UNSPLIT data yields, which come from `fjpt`. The two histograms
must be combined bin-by-bin in fjpt and TvsQCD.

Note the ORDERING CONSTRAINT: SF_QCD must be derived first, since
the Top-jet subtraction uses it to correct the QCD-jet term
(toptag/docs/scalefactors.md, "Note the SF_QCD*N(MC,QCD,tagged)
term").
